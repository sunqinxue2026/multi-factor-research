## 1. 目标与边界

使用 Python 3.10+、Pandas、NumPy、SciPy、Matplotlib、SQLAlchemy、MySQL 8.0 和 pytest，完成多股票行情到因子研究、组合选股及研究报告的可重复流程。SQLite可作为测试替代，但不能替代MySQL现场验证。

## 3. 数据结构与契约

### 行情表 MarketFrame

长表，唯一键 `(symbol, trade_date)`，研究元数据另存：

| 字段 | 类型/单位 | 约束 |
|---|---|---|
| symbol | string | 证券代码保留前导零 |
| trade_date | date | 明确交易市场和日历 |
| open/high/low/close | float64，CNY | 有效报价为正，缺失保留NaN |
| volume | 数值，股 | 真实零与缺失分开 |
| amount | 数值，CNY | 真实零与缺失分开 |

元数据包括 source、data_as_of、retrieved_at、price_type、units、file_sha256、universe描述、退市样本覆盖和日历来源。排序为symbol/date；横截面按date分组。MultiIndex可用于中间计算，文件与数据库仍使用显式键。

### 对齐与可交易性

基于显式市场日历和证券覆盖区间构造日期×股票面板，附 observed、is_suspended、is_listed、tradable 状态。缺少状态数据时标unknown，不将缺失自动判为停牌，也不将缺失成交量填0。

因子使用的价格不得因对齐而默认前向填充。组合估值若需沿用最近已知价格，必须单独标记 stale_price，不能拿它作可执行价格。窗口按市场交易日计数，缺失使窗口失效；上市前、退市后不补造行情。是否允许停牌价格参与研究是待确认规则。

### 研究中间表

- FactorFrame：date、symbol、factor_name、raw_value、processed_value、direction、valid、reason。
- LabelFrame：signal_date、symbol、entry_date、exit_date、horizon、forward_return、valid、reason。与可用于选股的特征物理分离。
- ICFrame：date、factor、horizon、n_valid、ic、rank_ic、reason。
- GroupFrame：date、factor、group_id、n_stocks、return、effective_start/end。
- TargetWeights：signal_date、execute_date、symbol、target_weight、score、rank。
- RunManifest：run_id、输入摘要、参数、代码版本、依赖版本、开始/结束时间、数据覆盖、限制与产物清单。

正式类型、SQL表结构和索引在对应阶段检查代码与版本后确定，任何迁移需先说明影响。

## 4. 因子定义与公式

设 C[s,t] 为统一口径收盘价，N为市场交易日回看窗口。

### 动量

`momentum_N(s,t) = C[s,t] / C[s,t-N] - 1`

默认研究20/60日；需要N+1个连续有效价格。区间从t-N收盘到t收盘，信息在t收盘后可得。正方向是研究假设，不保证有效；若使用跳过最近月的动量，应作为新定义而非暗改公式。

### 波动率

`r[s,t] = C[s,t]/C[s,t-1]-1`

`vol_N = std(r[t-N+1:t], ddof=1)`；`annual_vol_N = vol_N * sqrt(252)`。

需要N个有效收益及N+1个连续有效价格。不跨股票计算收益；不因缺失跳过一个交易日后仍称为日收益。默认低波方向为-1，含义为偏好低波，不将历史统计当作未来风险保证。

### 均值反转

`deviation_N = C[s,t] / mean(C[s,t-N+1:t]) - 1`

`reversion_N = -deviation_N`，默认高reversion代表更低于均线。均线含当天，需N个有效收盘价。原始偏离与方向调整后的反转得分分开记录，防止取负两次。20/60日分别研究。

三个因子是三个家族，不把20/60窗口默认全部当作6个独立等权因子。第一版组合建议每个家族选一个窗口；窗口选择在研究前配置，不能根据全样本表现事后挑选。

## 5. 预处理

每个日期独立处理截面：过滤非有限值→记录有效数→分位数截尾（建议1%/99%，插值方法固定）→Z-score→方向统一。

`z[s,t] = (clipped_x[s,t]-mean_t)/std_t(ddof=0)`。

若有效样本少于配置阈值或std=0，输出NaN并记录原因，不造可排名分数。初版建议完整因子样本参与组合，不默认缺因子后重新归一权重；需负责人确认。

时间序列标准化若后续支持，必须仅用历史滚动/扩展窗口，不能使用全样本均值和标准差。横截面同日统计不涉及未来日期，但依赖当日收盘信息，执行仍须滞后。

## 6. 标签与IC

建议主口径：t收盘产生因子，e为t后第一个市场交易日；H日标签为 `open[e+H]/open[e]-1`。例如H=5，从e开盘持有5个交易日间隔至e+5开盘。这样标签不包含无法在t收盘后获取的成交。

可选传统收盘标签 `C[t+H]/C[t]-1`仅作统计研究，必须标明不是可执行收益，不能与主口径混用。

执行日期不因缺少行情而悄悄向后移动：缺少入口/出口价或确定不可交易则标签无效。未来价格仅生成评价标签，不得进入特征、标准化、排名和调仓决策。

每日成对删除无效值，在有效横截面上计算 Pearson IC及Spearman RankIC；并列排名取平均秩。建议min_n=5，数学最低样本门槛与研究可靠性分开说明。常量因子或常量标签返回NaN和原因。

汇总有效日期：mean、std(ddof=1)、ICIR=mean/std、IC正值数/有效日期数。不默认年化ICIR。重叠H日标签导致时间相关，不能直接用独立样本t检验宣称显著；若需要显著性测试，须事前确定HAC或区块bootstrap及参数。

## 7. 分组与组合

同日独立分组，建议5组/10组。股票数不足则该日不分组。并列值建议采用平均秩分位区间，允许空组且记录，不任意按代码打散制造虚假差异。可提供确定性等数量分组作为备选，但必须披露并列值拆分。

每组等权平均有效标签，记录目标数量、有效收益数量和覆盖率。按配置覆盖阈值决定是否保留，不能无提示丢失停牌股票。

每日H日组均收益可作描述统计；累计曲线必须使用非重叠信号批次或独立逐日组合净值，不能每天把重叠H日收益复利。高减低为研究性多空价差，不代表可以实际融券成交。缺失组收益不默认填0。

综合得分 `score[s,t] = sum(w[k] * directed_z[k,s,t])`，默认3个家族各1/3。初版建议权重非负且和为1，单一方向由direction控制。股票按score降序，边界同分按symbol稳定排序并披露；选Top N，不足N时建议保留现金而非放宽筛选，待确认。

## 8. 调仓与项目一接入风险

每周/月最后一个市场交易日收盘计算信号，下一市场交易日开盘执行；样本尾部不完整周/月不自动当作完整周期。交易日历未知时不能声称准确的周末/月末调仓。

目标权重按信号时已知信息确定，执行日可用开盘价用于成交与数量核算，不可据开盘后表现重新选股。建议先卖后买、整手约束、成本计入，买不到或卖不出需保留原因和实际权重；详细规则第六阶段确认。

目标换手：将现金纳入时 `0.5*sum(abs(w_target-w_pretrade))`；另报实际单边成交额/NAV。不得混用不同口径。

已检查项目一 BacktestEngine.run：明确拒绝多股票，Snapshot仅有单个position_quantity/close_price，且账户不加仓；现有BUY/SELL信号接口不足以表达目标权重调仓。因此不能承诺直接无修改接入。

待重要决策确认：A 在项目一保留单股票接口的同时增加组合执行接口；B 项目二先完成研究性非重叠分组收益，第七阶段再单独评审组合执行适配。推荐阶段一至五按稳定研究接口推进，至第六阶段前确认扩展方案。不复制另一套完整回测引擎，不把价格收益研究伪装成真实组合回测。

绩效与项目一对齐：年化收益使用日历天数365.25，波动sqrt(252)、样本标准差、夏普无风险利率换算、包含初始净值的回撤、期末持仓估值。复用函数之前还需检查实际输入契约，不强行套用单股交易配对统计。

## 9. 验证与学习

每模块用手工小面板验证，测试包含乱序、并列、常量、缺失、停牌未知、不同股票价格数量级、短窗口和未来追加不改变历史特征。标签未来变化允许改变标签，不允许改变历史评分。

复杂度：M条已观察行情排序O(M log M)，常规滚动指标约O(M)，K因子保存O(KM)；完整对齐面板T×S可能比M大，内存O(TS)。每日截尾和排名典型O(T*S log S)，IC约O(TS)、RankIC约O(T*S log S)。调仓执行复杂度取决于未来选择的适配方案，不提前报性能数值。

技术说明主线：时间序列按股票回看，横截面按同日比较；IC检验线性关系，RankIC关注秩；相关性不代表可交易收益。低波/反转方向是事前研究假设。使用样本外验证和参数记录防止事后挑选；报告披露股票池、退市和公司行动覆盖。


## 10. 第一阶段补充：模块边界与状态语义

数据流：CSV与来源 → MarketFrame → CalendarPanel → FactorFrame → ProcessedFactorFrame → ScoreFrame/TargetWeights → 经确认的项目一组合接口 → PortfolioResult → 绩效与报告。
评价支路：CalendarPanel → LabelFrame；ProcessedFactorFrame 与 LabelFrame 按日期/股票配对 → IC与分组分析。LabelFrame不得成为评分或选股模块的输入。

- CsvReader只负责读取与类型转换；PanelBuilder负责唯一键、日历和覆盖区间；FactorCalculator只接收已对齐的历史面板。
- Preprocessor按日期独立输出截尾阈值、均值、标准差、有效数和无效原因；Scorer只接收可用的方向统一因子。
- RebalancePlanner输出目标权重，不负责模拟成交；ExecutionAdapter负责将目标权重传给经批准的组合执行契约。
- Reporter只汇总已存在的结果，不反向修改窗口、因子方向或股票池。
- 无代码阶段使用上述职责名称描述边界，不将其称为已存在的类或函数。

状态采用可空布尔：observed表示是否存在源记录；is_listed、is_suspended、tradable不能在缺少证据时默认为True或False。合法OHLC和正成交量不证明真实订单一定可成交。unknown意味着证据不足，而非正常交易。

覆盖区间需记录依据：有上市/退市资料时按时点覆盖；只有行情时只能描述观察到的区间，不能用首末条记录推断真实上市/退市日期。日历存在不代表历史股票池已完整。

多市场数据第一版拒绝静默共用日历；须声明一个研究市场和对应日历。复权口径必须一致。前复权数据可能因后续公司行动发生历史修订，文件摘要只能锁定版本，不能证明时点可获得性；缺少时点价格版本和公司行动资料时报告此局限。
