# 技术决策

## 已观察事实
项目一行情8列可兼容；BacktestEngine拒绝多股票，Snapshot含单股票数量和收盘价。不能在项目二仅更换策略对象就实现组合回测。

## 待确认提案
1. 命名包multi_factor_research；显式长表作为模块边界，内部按symbol或date分组。
2. 日历必须来自声明的数据源，不用工作日自动冒充交易日；缺失停牌状态标unknown，不自动填0或补成交价。
3. 标签默认下一交易日开盘到H个交易日之后开盘；传统close-to-close仅另作统计标签。
4. 每日期独立截尾和标准化；完整因子样本评分，零标准差不强行填0。
5. 分组并列使用平均秩，可空组；不直接复利重叠H日收益。
6. 第六阶段前评审项目一组合执行扩展；保持旧接口兼容，不复制完整引擎。

## 必须解释的影响
引擎扩展会涉及多持仓、目标权重、卖出/买入顺序、整手和费用以及新快照契约；如需数据库表结构变更，先提出迁移及旧数据兼容方案。未获确认不执行。

MySQL表设计、显著性检验、历史股票池和复权/公司行动处理均未定稿。不得宣传消除幸存者偏差、完整模拟成交或获得有效alpha。


## 本轮接口复核与新增提案

实际复核项目一engine/backtest.py：BacktestEngine.run显式拒绝多股票，Snapshot包含单个position_quantity和close_price。performance/analyzer.py的交易统计也以单股买入至退出配对为前提。既不能直接套组合，也不能用多次单股回测求平均代替共享现金组合。

建议研究层先保持独立；组合执行适配在第六阶段前评审，若需改项目一，先列旧调用兼容、现金和多持仓结构、数据库迁移、费用及无法成交规则。此建议尚未批准。

新增数据提案：状态用可空布尔；观察区间不等于上市区间；日历和股票池分别版本化；前复权历史修订风险明确披露。未获确认不固化业务行为。

## 第二阶段已采用决策
- 采用data.py单文件承载本阶段紧密相关的数据契约；后续规模扩大再拆分，不预建空模块。
- validate_market_frame严格拒绝非法数据和重复键，包括完全相同重复行；这是项目二入口校验，不是复制项目一的清洗分类器。不自动解决冲突，不删除原文件记录。
- TradingCalendar接受显式开放日，市场、来源、版本必填；无日历允许read_market_csv检查原始数据，但build_calendar_panel拒绝正式对齐。
- 面板使用所提供日历×输入已观察股票，边缘缺失也是unknown；不是历史上市区间或时点股票池。日历可包含零行情日，但不得晚于data_as_of。多市场不混合。
- observed区分无记录；price_complete区分价格缺失；is_listed/is_suspended使用nullable boolean。tradable仅为False或NA：缺价/明确停牌/明确未上市为False，其余仍未知，不承诺真实可成交。
- 停牌资料使用逐日显式状态DataFrame，不前向传播；本阶段CLI没有状态文件上传选项。未来模块须自行按确认规则决定停牌价格能否研究。
- 不填充价格、成交量和成交额，零量不自动判停牌。原始非法行抛错，不生成accepted/rejected分类文件。
- 来源类型、单位、截至日期显式校验。只声明单一市场，不通过股票后缀自动验证其真实市场；日历真实性依赖提供者。
- 当前无SQL表结构、无数据库迁移、无项目一修改。来源摘要锁定文件版本，不证明历史时点可得或消除幸存者偏差。
- 正式入口拒绝覆盖已有输出目录；输出文件非原子提交，失败时可能保留部分文件。
- 隔离环境实测Pandas 3.1.1；普通环境检查显示2.3.3，两者不能混记。依赖按Python版本限定：3.10仅选Pandas 2.x/NumPy<2.3/pytest<9；兼容性尚无3.10实测。本阶段未安装依赖。
