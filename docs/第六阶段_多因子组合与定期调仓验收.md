## 3. 已实现的功能

### 3.1 综合评分

接口接收PreprocessingResult和TradingCalendar。windows和weights分别是三个因子名称到窗口和权重的映射；不隐式归一化。零权重因子也必须有效，遵循“所选三个因子全部有效”的已确认规则。

检查非空、字段、日期、日历身份、联合键唯一、布尔标记、有限值、窗口及代码；CASH是保留代码。先建立所有已观察股票日期，再左连接各指定窗口，缺因子不静默删行。只消费oriented_value，不消费标签。

scores保留各因子值和标记，新增score、score_valid、score_reason、rank。排序为日期升序、评分降序、代码升序；无效分数保留缺失且不排名。不修改输入。

### 3.2 调仓与目标

周按W-SUN分期，月按M分期。相邻显式日历位置跨期时，前一天为signal_date、后一天为execution_date。日历尾部无法确认的周期跳过；不使用普通工作日推断真实市场假期。

仅在信号日使用有效排名前N只，每只1/N，现金为1-k/N。没有该日截面或没有有效候选则全现金，不沿用旧目标。targets显式列现金；changes以新旧股票代码并集列出退出股票的0目标及现金变化；rebalances记录选中数量、现金、目标换手及状态。

### 3.3 结果契约

PortfolioResult包含scores、targets、changes、rebalances、parameters、文件摘要、日历来源及版本。无调仓日时，三张计划表仍有固定列。执行层应按execution_date读取计划；target不是实际持仓，changes不是成交。

## 5. 核心数据结构、算法和公式

设三个定向标准化值为z，权重为w：

```text
score(s,t) = Σ w_f * oriented_value(s,t,f)
w_f >= 0, Σw_f = 1
股票目标 = 1/N；现金目标 = 1-k/N
目标单边换手 = 0.5 * Σ资产（包含CASH）|新目标-旧目标|
```

手算评分：A因子[10,0,0]、C[2,2,2]、B[1,1,1]，权重[0.5,0.25,0.25]，分数分别5、2、1，排名A/C/B。

手算换手：旧A50%+现金50%，新B50%+现金50%，换手=(50%+50%+0)/2=50%；再转全现金为50%。从全现金到全股票为100%，不是50%。

DataFrame长表经左连接构成每股票日期的评分表；groupby/cumcount稳定排名；日历PeriodIndex识别边界；按日期字典避免反复扫描评分表；新旧目标字典及集合并集记录退出。初始previous={CASH:1}。

## 6. 采用该方案的原因

等权透明且提供可解释基线，不用全样本IC反向挑权重。严格完整因子避免每只股票用不同模型评分。固定1/N可显示不足额现金，避免无声提高剩余股票仓位。同分代码排序使结果可重复，但不是额外alpha信息。

日历跨期确认避免把样本尾部误当完整周期；只使用信号时点评分。保留全现金及退出计划，使执行层知道“无候选”意味着退出目标而非保持仓位。包含现金的目标换手能明确解释初始建仓。

## 7. 可选替代方案

- 缺因子重分权：覆盖更多股票，但不同股票模型不可比，未采用。
- 余下股票满仓：提高资金利用率但改变暴露，本版留现金。
- 同分全部纳入：减少代码优先偏好，但可能超过N及改变权重。
- IC加权/优化权重：必须训练验证分离并对照等权，不在本阶段实现。
- 持仓漂移后实际换手：更贴近交易，但需账户和成交，留第七阶段。
- 在线日历事件：可在下周期首日确认前日信号；当前离线以显式日历下一位置识别，不能读取未来价格。

## 8. 性能瓶颈和后续优化方向

设选定因子输入R行、股票日期P行、日历T位置、调仓K次、股票S只。固定三次合并常见哈希路径约线性，评分排序保守O(P log P)，目标变更至多O(K*S log S)含代码排序；额外空间O(R+P+K*S)含复制和输出。日期分期O(T)，实际不保证所有Pandas底层操作最坏线性。

瓶颈可能是深副本、三次merge及全量评分排序；可按日期分块、宽表一次pivot、仅信号日TopN优化，但后者会改变全日评分交付，需要评审。未做大规模性能基准，不能宣称高性能或给出吞吐量。

## 9. 面试官可能追问的问题及回答思路

**为何不能用第五阶段IC挑最高权重？** 全样本选择将评价信息回流模型，带来过拟合；当前等权/用户预先配置，后续优化必须分训练验证。

**缺一个因子能否用两个？** 当前build_portfolio_plan要求三个*_valid全部True；test_ties_shuffle_and_zero_weight_still_requires_factor也验证零权重不绕过契约。

**为何信号日不能成交？** 当日收盘后因子才确定，rebalances把execution_date设为下一显式市场日期；不是同日收盘成交。

**无候选是不是维持原仓？** 不是，本版生成全现金目标，changes保留旧股票退出0；test_exit_all_cash_and_turnover_hand手算验证。卖不出去仍可能有实际持仓，目标与成交不同。

**如何验证未来不变？** test_append_and_modify_future_preserve_confirmed_history比较追加并改变未来数据后的历史评分和已确认计划；不要求原尾部未确认周期永远没有新增计划。不证明股票池及复权时点无偏。

**为何目标换手不能直接算手续费？** 实际数量受股价漂移、整手、余额和无法成交影响；目标权重差只是研究配置变化，第七阶段需实际成交金额。
