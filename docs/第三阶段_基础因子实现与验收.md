## 3. 已实现的功能

### 3.1 入口与数据契约

`calculate_factors(panel, calendar, *, windows=(20, 60), annualization_days=252)`返回FactorResult。

1. 窗口必须是互不重复、至少为2的Python整数；拒绝空窗口、布尔、浮点和字符串。统一要求N≥2，避免样本波动率只有一个收益的无定义情形。
2. 年化天数必须为正整数。日历市场、来源、版本须与面板相符，且不晚于数据截至日期。
3. 使用已有validate_market_frame重新校验八列行情，拒绝重复键和非法值。
4. 验证股票×显式日历完整网格，不允许先删缺失行再计算；乱序输入允许，经校验排序。
5. 收盘价足以计算价格统计，不因缺开盘价而填充或篡改收盘价。状态与观测字段若存在则随输出保留，不被用于推断投资资格。

### 3.2 输出

每只股票、每个日期、每个窗口产生三行因子。关键列：symbol、trade_date、factor、window、value、valid、reason、annualized_value，以及已有状态列。

- valid表示窗口足以计算价格因子，不表示股票可买卖。
- reason：valid、insufficient_history（起始位置不足）、missing_close_in_window（位置足够但窗口缺价）。起始阶段即使同时有缺价，仍优先标记历史长度不足。
- annualized_value仅波动率有值，其余NaN是字段不适用，不是计算失败。
- mean_reversion当前是原始均线偏离，尚未乘以负方向；动量、低波及反转方向只是研究假设。
- 参数保存在FactorResult.parameters；行情摘要与日历来源、版本随结果返回。没有将所有元数据复制进长表每行。

### 3.3 状态边界

本阶段只计算价格统计：未知tradable不阻止因子计算；明确停牌或未上市但存在收盘价时也保留原始统计与状态。测试明确覆盖该行为。后续必须单独建立可投资样本筛选规则，不得直接将valid当作选股资格。这个设计不新增停牌成交规则，不证明时点股票池完整；投资资格在组合阶段须由负责人确认。

## 5. 核心数据结构、算法和公式

令C(s,t)为日历位置t的统一口径收盘价。

- 动量：C(s,t)/C(s,t−N)−1，且[t−N,t]全部N+1个收盘有效。仅端点有效不足以接受。
- 日收益：r(s,t)=C(s,t)/C(s,t−1)−1；pct_change(fill_method=None)，不填价。
- 波动率：sqrt(sum((r−mean(r))²)/(N−1))，最近N个日收益；年化乘sqrt(A)，默认A=252。
- 偏离：C(s,t)/mean(C(s,t−N+1:t))−1，含当日N个收盘。

逐股票groupby，使用shift、rolling(count/mean/std)计算。FactorResult为数据表、参数字典和追溯字段；输出长表按股票、日期、因子、窗口稳定排序。先按股票做时间序列计算，不包含同日横截面标准化，不使用全样本统计量。

## 6. 采用该方案的原因

1. 与第二阶段接口直接连接，显式验证日历，避免稀疏行序号冒充交易日间隔。
2. count对动量窗口内部价格有效性把关；收益不填充，波动率必须有N个实际日收益。
3. 长表统一表示不同因子和窗口，方便后续按日期、因子做横截面预处理。
4. 保存原始偏离与有效原因，便于解释正负号与窗口失效。
5. 原始价格统计与可投资资格分离，不把unknown强制填True/False，不擅自制定撮合规则。
6. 使用现有Pandas/NumPy，无新增依赖；无项目一耦合或数据库迁移。

## 7. 可选替代方案

| 替代 | 优点 | 当前取舍 |
|---|---|---|
| 日期×股票宽矩阵 | 批量滚动可减少Python分组开销 | 状态和长表输出需要重组，先保持统一契约 |
| NumPy累计和/平方和 | 可控制窗口计算 | 数值稳定性及缺失边界复杂，先用成熟rolling |
| 每日历史切片重算 | 直观易审计 | 通常O(PN)，不适合扩大规模 |
| 因子时直接过滤停牌 | 研究表更小 | 混淆价格统计与投资资格，必须先确认样本规则 |
| 均线偏离直接取负 | 评分方向直观 | 隐藏原始口径，方向统一应在第四阶段记录 |

## 8. 性能瓶颈和后续优化方向

设P=S×T，K为窗口数。固定三因子输出L=3KP。

- 初始排序O(P log P)。每个窗口滚动计算通常随P线性增长，主计算约O(KP)。
- 当前每只股票从states全表过滤，额外约O(SP)，是明确可优化点。
- 最终长表排序O(L log L)，存储与中间副本约O(L+P)，并有Pandas对象开销。
- 可以先按symbol对状态建分组索引、分股票/窗口写出、对同窗口中间结果复用，再考虑宽矩阵或分块。
- 本阶段只执行极小样本，没有内存峰值或全市场性能基准，不承诺加速倍数；示例耗时不等于吞吐量报告。

## 9. 面试官可能追问的问题及回答思路

**为什么20日动量要21个价格？** N个收益间隔有N+1端点，calculate_factors同时检查窗口count，避免跨缺失拼接。

**波动率为什么ddof=1，而标准化以后可能ddof=0？** 前者是收益样本标准差估计，后者是同日研究截面的缩放口径，目的不同，必须各自记录和测试。

**涨10%再跌10%为什么不是0？** 累计收益连乘1.1×0.9−1=−1%，不是简单相加；手算测试精确覆盖。

**mean_reversion负值为何可能评分更高？** 原始偏离为负表示低于均价；如果采用反转假设，应在预处理后乘−1，并通过IC等检验，不能把假设写成结论。

**缺口两端都有效为何仍不给动量？** 项目契约要求连续窗口可审计；count约束强于纯端点公式，避免把不同覆盖质量的窗口混用。

**如何证明不用未来？** 只向后shift/rolling，按股票分组；追加或修改未来价格后逐字段比较历史输出。仅覆盖这些路径，不证明股票池与复权时点无偏差。

**valid和tradable有什么区别？** valid只说明价格窗口足以计算；停牌且有价仍可能有原始统计，但下单资格必须另行筛选，不能用valid替代。

**为什么出现跨版本错误？** Pandas字符串dtype及MultiIndex比较语义存在差异，实际3.10测试暴露后统一输出键类型，并对唯一键集合做完整性检查，没有删除失败断言。
