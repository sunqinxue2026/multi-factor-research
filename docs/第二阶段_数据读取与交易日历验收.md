## 1. 本阶段目标与验收范围

建立兼容项目一八列CSV的多股票数据层，将输入行情整理为按显式市场交易日历对齐的研究面板，为后续因子计算和横截面分析提供稳定接口。

本阶段解决以下问题：

1. 多股票行情能否批量读取，股票代码前导零是否保留。
2. 字段、日期、股票日期联合键、数值和OHLC关系能否严格校验。
3. 来源、复权口径、单位和数据截至日期能否明确记录。
4. 能否按给定交易日历保留缺失位置，而不伪造报价。
5. 能否区分零成交、字段缺失、整条记录缺失及未知市场状态。
6. 能否提取单日横截面，并且不让调用者修改影响原始面板。
7. 能否通过正式命令行生成可追溯的面板和运行摘要。

本阶段不实现因子、预处理、未来收益标签、IC、分组、组合调仓、数据库写入或回测适配；没有复制或修改项目一的回测引擎。

## 3. 数据契约与实现接口

### 3.1 行情八列

```csv
symbol,trade_date,open,high,low,close,volume,amount
```

- `symbol`必须是非空字符串且不含首尾空格；CSV按字符串读取，保留前导零。
- `trade_date`严格为YYYY-MM-DD，并进一步验证真实日期；不接受整数日期、斜杠格式或非法日期。
- OHLC有效值必须为正，成交量和成交额有效值非负；允许真实缺失。
- 非法数值字符串、无穷值、布尔数值直接拒绝。
- 非缺失价格必须满足low≤open/close≤high及low≤high。
- `(symbol, trade_date)`必须唯一；即使完全相同的重复行也拒绝，不自行决定如何去重。
- 输出只保留标准八列，并按股票、日期稳定排序；不修改调用者输入。

### 3.2 来源与日历

`DatasetMetadata`记录来源、市场、复权口径、截至日期、合成标记、股票覆盖描述、退市样本声明和单位。

当前只接受CNY／股／CNY，不自动换算；复权口径必须为未复权、前复权或后复权。类型注解不代替运行时检查，`__post_init__()`负责关键类型和值验证。

`TradingCalendar`记录开放日期、市场、来源和版本。日历非空、日期唯一，构造时排序；CSV只允许`trade_date`一列。不用普通工作日推断市场开放日。行情市场必须与日历市场一致，行情必须属于给定日历，行情和日历末日不能晚于`data_as_of`。

### 3.3 实际接口与责任

| 接口 | 输入与输出 | 核心保证 |
|---|---|---|
| `validate_market_frame()` | DataFrame→标准化副本 | 字段、数值、日期、价格关系、联合键和排序 |
| `read_market_csv()` | CSV路径＋元数据→`MarketDataset` | 同一份文件字节用于解析和SHA-256；记录文件名 |
| `TradingCalendar.from_csv()` | 日历CSV＋市场／来源／版本→日历对象 | 明确开放日及来源声明 |
| `build_calendar_panel()` | 行情集合＋日历＋可选状态→`PanelResult` | 补日期位置，不补行情；逐日状态不传播 |
| `PanelResult.cross_section()` | 日期→该日股票数据副本 | 横截面提取及副本隔离 |

## 4. 已实现流程、状态与输出

### 4.1 正式链路

```text
行情CSV＋来源JSON＋交易日历CSV
    → 参数解析及元数据校验
    → CSV字节快照、摘要与行情校验
    → 市场和日期范围检查
    → 股票×交易日MultiIndex
    → reindex保留缺失位置
    → 逐日上市／停牌状态及阻止条件
    → panel.csv＋summary.json
```

`MarketDataset`保存行情、元数据、摘要和文件名；`PanelResult`保存面板、元数据、日历来源和版本及行情摘要。数据类不是全部不可变对象，调用者仍须遵守接口契约；构建面板时会重新校验行情。

### 4.2 状态字段

| 字段 | 含义及当前行为 |
|---|---|
| `observed` | 原始输入是否存在该股票日期记录 |
| `price_complete` | 当天OHLC是否全部非缺失，不表示一定可成交 |
| `is_listed` | 明确的逐日上市事实；无资料为可空布尔未知 |
| `is_suspended` | 明确的逐日停牌事实；无资料为未知，不由零成交推断 |
| `tradable` | 缺价、明确停牌或明确未上市时为False；其余仍为未知，不输出True |
| `status_reason` | 主要状态原因，不是所有异常的完整列表 |

原因覆盖优先级按实际赋值顺序为：明确未上市＞明确停牌＞缺少记录＞缺少价格＞执行条件未知。多个问题可能同时存在，仍应结合其他字段判断。

状态表仅允许联合键及`is_listed`、`is_suspended`，拒绝重复键、面板外键和非布尔非空值；状态仅作用于给定日，不前填到其他日期。

### 4.3 导出保护与追溯

入口通过`exist_ok=False`拒绝覆盖已有输出目录。先写面板，再写摘要；输出失败可能留下部分文件，不是文件级原子事务。

摘要记录输入／面板／缺失数量、元数据、行情摘要、日历摘要和版本、UTC开始时间、运行耗时、Python及Pandas版本和限制。耗时来自`perf_counter()`，不是对外承诺的性能指标。

行情解析与摘要使用同一字节快照；日历在入口中解析后另行读取计算摘要，不能声称所有输入都已实现不可变快照或防止读取间被修改。来源JSON未单独保存原始字节摘要。

## 8. 数据结构、算法、复杂度与替代方案

### 8.1 为什么这样设计

- 数据契约与日历分开：来源行情不等于完整市场日历，不能从有报价的日期反推所有开放日。
- 先校验再对齐：错误数值和重复键必须在进入研究面板之前暴露。
- 完整网格保留缺口：后续窗口按市场日推进，而不是跳过缺失记录后计算错误的相邻收益。
- 可空布尔：区分明确False和没有证据；零成交不能证明停牌。
- 复制输入和返回横截面：降低调用者意外修改共享数据的风险，但不等于完整不可变系统。
- 入口与业务分离：业务模块不依赖命令行参数和输出目录，方便测试及后续接口复用。

### 8.2 复杂度

设原始M条行情、S只股票、T个交易日，完整面板P＝S×T。

| 操作 | 规模分析 |
|---|---|
| 固定列校验 | 约O(M) |
| 行情排序 | O(M log M) |
| 构造MultiIndex与对齐 | 主要随M及P增长，通常约O(M+P)，另有索引开销 |
| 面板存储 | O(P)，多副本及中间对象增加峰值内存 |
| 当前横截面过滤 | 扫描约O(P)，另需复制当日结果 |
| CSV字节与解析 | 文件字节及DataFrame同时占用内存 |

上述是算法规模估计，没有进行性能基准，不承诺吞吐量或加速倍数。

### 8.3 替代方案及取舍

| 替代方案 | 优点 | 需要额外处理的问题 |
|---|---|---|
| 稀疏长表 | 缺失多时节省内存 | 窗口必须验证市场日间隔，不能直接按记录滚动 |
| 宽表（日期×股票） | 某些收益矩阵计算方便 | 多字段、状态、来源管理不如长表直接 |
| 数据库按需读取 | 可控制研究范围和内存 | 查询、版本、一致性和连接管理更复杂 |
| 按股票分块 | 降低峰值内存 | 横截面处理需要重新汇总同日数据 |
| 日期索引／分区 | 提升频繁横截面访问效率 | 需评估维护复杂度和实际瓶颈 |

当前选择优先保证语义明确、可审计和教学可解释，后续基于实测再优化。

## 9. 面试追问与结合真实代码的回答

### 为什么不直接删除缺失行？

`build_calendar_panel()`通过`MultiIndex.from_product()`和`reindex()`保留日期缺口。删除后相邻记录可能跨多个市场交易日，不能当作单日日收益。当前只保留缺口，第三阶段还必须正确验证连续窗口。

### 为什么不直接前向填充？

因子研究价格与账户估值价格用途不同。沿用旧价格可以是另行规定的估值规则，但不能伪装成当天真实报价。本模块不自动填充，更不将填充值当作可成交价格。

### 时间序列与横截面有什么区别？

同一股票跨日期是时间序列，未来动量和波动率沿该方向回看；`cross_section()`取同一天的多只股票，后续标准化和排名在这个截面比较。当前阶段只提供结构，还未计算两类统计。

### 为什么零成交不自动标停牌？

零值是输入事实，停牌是需要外部资料证明的市场状态。代码只在提供逐日布尔状态时记录明确停牌，否则未知，避免把推断写成事实。

### 如何防止输入被修改？

校验函数复制标准列，构建面板使用新的结果，横截面返回深复制；测试比较原输入并主动修改横截面，确认不影响原结果。但DataFrame对象本身仍可变，不应宣称所有对象完全不可变。

### SHA-256证明了什么？

`read_market_csv()`用同一字节快照解析和计算摘要，证明记录的文件身份；不能证明数据真实、具备再分发授权、正确复权或历史时点可获得。

### 如何处理幸存者偏差？

面板股票集合来自输入中观察到的股票，不含完整历史股票池和退市信息，因此无法消除幸存者偏差。来源元数据和运行摘要明确披露这一点，不以全样本股票集合冒充历史可投资股票池。

### 能否说追加未来数据不影响历史？

只能针对已测试的同一股票集合案例这样描述。未来首次出现的新股票会扩展完整网格，历史横截面的股票位置可能变化，后续必须引入时点股票池约束或显式研究覆盖规则，不能直接把新增的历史空行作为当时可投资样本。

## 10. 已知限制、尚未实现与修改影响

1. 只用合成行情和合成日历验证，尚无真实多股票、官方日历交叉验证。
2. 日历来源和版本是声明，程序不认证真实性或完整性。
3. 面板使用全部观察到的股票×给定日历，边缘缺失不代表未上市或已退市。
